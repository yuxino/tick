## 原生时段验收清单

1. 先记录基线任务列表和当前用户身份，只安装本页哈希对应的安装包；确认未出现 UAC，安装目录、开始菜单和卸载项都属于当前用户。
2. 启动 Tick，创建唯一的验收任务。工作目录使用只含本次测试数据的 `Tick Acceptance 空格 & 中文` 目录，参数覆盖空格、中文、空字符串、尾随反斜杠和 `&|<>^%`；不得放入凭据或私人内容。
3. 核对 Task Scheduler XML：`Tick.job-*`、Tick Source/URI、当前用户、`InteractiveToken`、`LeastPrivilege`、唯一 Exec action，以及固定的 `tick.exe --run-scheduled-job <id>`；用户命令不得出现在 XML action。
4. 完成启用、立即运行、stdout/stderr、工作目录、参数和环境变量核对；再运行长任务并停用，确认 Tick runner 和整棵子进程树退出，之后重新启用验证调度语义。
5. 验证关闭到托盘、左键显隐、右键菜单、菜单退出与重新启动；保存只含 Tick 和隔离测试数据的安全截图。
6. 删除且仅删除本次验收创建的 Tick 任务，证明基线中的其他任务未变；退出、卸载并检查应用进程、安装目录、快捷方式与卸载项。保留产品数据仅按卸载器实际语义记录，不扩大清理范围。

## 尚未获得的证据与边界

- 尚未在 guest 中证明安装、启动、Task Scheduler 真实注册/触发/停止、日志、托盘、退出和卸载；host 交叉构建不能替代这些证据。
- NSIS 启动器本身是 x86，会由 Windows 11 ARM64 的兼容层运行；安装后的 `tick.exe` 是原生 ARM64。
- 当前包未签名，只用于受控开发验收，不代表可公开分发。
- NSIS 未显式配置安装器语言，当前使用 Tauri 默认英文文案。
- UI 每次只读取日志末尾 256 KiB，但单个长期运行任务的日志文件仍可能持续增长。
- Windows 子进程只显式创建三个可继承的标准流句柄；当前实现尚未使用 `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` 对进程内其他潜在可继承句柄做额外白名单收窄。
