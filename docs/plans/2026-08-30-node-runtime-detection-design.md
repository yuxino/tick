# Node.js 运行环境检测设计

## 目标与边界

Tick 的默认任务是 JavaScript，并由系统中的 Node.js 执行。安装包不内置 Node.js，也不替用户下载、安装或修改 PATH。应用启动时检测默认 Node.js；缺失时持续显示原因和下一步，并允许用户在自行安装后重新检测。设置页展示实际验证过的版本与解释器路径。

Windows 不能只依赖 Tick 启动时继承到的 PATH：用户安装 Node.js 后，已运行的 GUI 进程可能仍持有旧环境。检测顺序因此是当前 PATH、NVM_SYMLINK、Program Files/LocalAppData 常见位置，以及当前用户和本机的 Node.js 注册表安装目录。每次重新检测都重新读取这些来源，不缓存结果。

## 二次校验

界面提示不能代替执行边界。保存默认 JavaScript 任务、启用已有 Node.js 任务、立即运行 Node.js 任务和调试 AI 脚本前，Rust 后端都会以实际解释器命令运行一次有超时限制的 `--version` 探测。调试和 Windows 计划任务执行也使用同一套解析；旧任务中保存的裸 `node.exe` 会在每次运行时重新解析成当前可用的绝对路径。探测失败时拒绝操作，说明 Tick 未检测到 Node.js、用户需要自行安装并重新检测，以及 Tick 不会自动安装或修改 PATH。

手动配置的非 Node.js 解释器和不需要解释器的可执行脚本不受影响。检测进程在 Windows 上隐藏控制台窗口，输出长度受限，不保存环境信息。

## 验证

单元测试覆盖默认内联任务、Node.js 自定义路径、非 Node.js 解释器、直接执行脚本，以及 PATH、NVM、官方目录、用户目录和注册表候选路径的顺序与去重。完整检查覆盖 Rust 格式与 Clippy、全部 Rust/前端回归测试和生产构建；Windows x64 交叉检查和 CI 构建确认注册表/API 声明、异步边界及安装包。原生复测分别验证“未安装时提示”和“安装后重新检测并真实运行”，不能用 CI 代替。
