# Node.js 运行环境检测设计

## 目标与边界

Tick 的默认任务是 JavaScript，并由系统中的 Node.js 执行。安装包不内置 Node.js，也不替用户下载、安装或修改 PATH。应用启动时检测默认 Node.js；缺失时持续显示原因和下一步，并允许用户在自行安装后重新检测。

## 二次校验

界面提示不能代替执行边界。保存默认 JavaScript 任务、启用已有 Node.js 任务、立即运行 Node.js 任务和调试 AI 脚本前，Rust 后端都会以实际解释器命令运行一次有超时限制的 `--version` 探测。探测失败时拒绝操作，说明 Tick 未检测到 Node.js、用户需要自行安装并重新检测，以及 Tick 不会自动安装。

手动配置的非 Node.js 解释器和不需要解释器的可执行脚本不受影响。检测进程在 Windows 上隐藏控制台窗口，输出长度受限，不保存环境信息。

## 验证

单元测试覆盖默认内联任务、Node.js 自定义路径、非 Node.js 解释器和直接执行脚本的分类。完整检查覆盖 Rust 格式与 Clippy、全部 Rust/前端回归测试和生产构建；Windows x64 交叉检查和 CI 构建确认命令声明、异步边界及安装包。
